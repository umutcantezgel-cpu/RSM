## Challenges

### [Low] Challenge 1: Hardcoded Locale Limitation in Middleware matcher

*   **Assumption challenged**: The middleware matches only `/` and `/de` path prefixes.
*   **Attack scenario**: If additional locales are supported in the future (e.g., English, French) without manually editing `proxy.ts` matcher array (`matcher: ['/', '/(de)/:path*']`), requests to these new locales will bypass the middleware, causing layout or locale resolution inconsistencies.
*   **Blast radius**: High if new locales are added. Currently low since only German (`de`) is enabled.
*   **Mitigation**: Generate the matcher dynamically or keep it updated if the `routing.locales` array expands.

### [Low] Challenge 2: Client-Side Intubation of translation fallbacks in test environments

*   **Assumption challenged**: The test environment can resolve all Next-Intl client contexts without environment fallbacks.
*   **Attack scenario**: During testing, `LoginForm` logs an `ENVIRONMENT_FALLBACK` error due to lacking mock values for some Next-Intl server/client context variables.
*   **Blast radius**: None for production, but logs verbose error stack-traces during test executions.
*   **Mitigation**: Update test execution configuration to silence known Next-Intl fallback logs or provide full environment variables in test setup.
